## 2. 核心代码实现

### 2.1 Axios 封装与统一拦截（`src/api/request.js`）

所有 API 请求经过统一 axios 实例，自动注入鉴权头并解包后端统一响应格式 `{code, message, data, trace_id}`。

```javascript
import axios from 'axios'
import { ElMessage } from 'element-plus'
import { getToken, getOperator, removeToken } from '@/utils/auth'
import router from '@/router'

const service = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL || '',
  timeout: 15000,
})

// 请求拦截：注入 Bearer Token 与 X-Operator（后端操作人解析优先级：Token映射 > X-Operator > default）
service.interceptors.request.use((config) => {
  const token = getToken()
  if (token) config.headers['Authorization'] = `Bearer ${token}`
  const operator = getOperator()
  if (operator) config.headers['X-Operator'] = operator
  return config
})

// 响应拦截：code===0 返回 data；非 0 抛业务错误；401 自动登出
service.interceptors.response.use(
  (response) => {
    const res = response.data
    if (res && typeof res === 'object' && 'code' in res) {
      if (res.code === 0) return res.data
      ElMessage.error(res.message || '请求失败')
      return Promise.reject(new Error(res.message))
    }
    return res // /healthz 等非标准接口直接返回
  },
  (error) => {
    const status = error.response?.status
    if (status === 401) {
      ElMessage.error('登录已过期，请重新登录')
      removeToken()
      router.push('/login')
    } else if (status === 429) {
      ElMessage.warning('请求过于频繁，请稍后再试')
    } else if (status === 503) {
      ElMessage.error('服务暂不可用（熔断开启）')
    } else {
      ElMessage.error(error.response?.data?.message || error.message)
    }
    return Promise.reject(error)
  }
)
```

**设计要点**：
- 后端响应格式为 `{code:0, message:"success", data:{...}}`，拦截器自动解包 `data`，业务层直接拿到业务数据。
- 分页接口的 `data` 为 `{list, pagination:{page,page_size,total,total_pages}}`。
- 401 时清除本地 Token 并跳转登录页，避免死循环。

### 2.3 认证状态管理（`src/stores/auth.js`）

网关采用静态 Bearer Token 鉴权（`config/default.yaml` 中配置），无独立登录接口。登录逻辑为：用户录入 Token → 暂存 → 调用 `/api/v1/system/config` 验证有效性 → 成功则进入系统。

```javascript
export const useAuthStore = defineStore('auth', {
  state: () => ({
    token: getToken(),
    operator: getOperator(),
    configSnapshot: null,
  }),
  actions: {
    login({ token, operator }) {
      this.token = token
      this.operator = operator || 'admin'
      setToken(token)
      setOperator(this.operator)
    },
    logout() {
      this.token = ''
      this.operator = ''
      removeToken()
    },
    async fetchConfig() {
      this.configSnapshot = await getConfig()
    },
  },
})
```

### 2.5 路由管理页核心逻辑（`src/views/RouteList.vue`）

路由管理是功能最完整的页面，涵盖列表/搜索/分页/新建/编辑/删除/启停。

**列表加载与分页**：

```javascript
const query = reactive({ page: 1, page_size: 20, path: '', method: '', target_service: '' })

async function loadList() {
  loading.value = true
  try {
    const res = await listRoutes({
      page: query.page,
      page_size: query.page_size,
      path: query.path || undefined,       // 空字符串不传，避免后端误匹配
      method: query.method || undefined,
      target_service: query.target_service || undefined,
    })
    list.value = res?.list || []
    total.value = res?.pagination?.total || 0
  } finally {
    loading.value = false
  }
}
```

**启用/禁用开关**（PATCH `/routes/:id/status`）：

```javascript
async function handleStatusChange(row, val) {
  row._statusLoading = true
  try {
    await patchRouteStatus(row.id, val)
    ElMessage.success(val ? '已启用' : '已禁用')
    row.enabled = val
  } catch {
    row.enabled = !val  // 失败回滚开关状态
  } finally {
    row._statusLoading = false
  }
}
```

**表单提交**（新建 POST / 更新 PUT 共用同一弹窗，`isEdit` 区分）：

```javascript
async function handleSubmit() {
  await formRef.value.validate(async (valid) => {
    if (!valid) return
    submitting.value = true
    try {
      if (isEdit.value) {
        await updateRoute(editId.value, { ...form })
        ElMessage.success('路由更新成功')
      } else {
        await createRoute({ ...form })
        ElMessage.success('路由创建成功')
      }
      dialogVisible.value = false
      loadList()
    } finally {
      submitting.value = false
    }
  })
}
```

**表单字段与后端 `CreateRouteRequest` 一一对应**：`route_name`、`path`、`method`、`target_service`、`rewrite_path`、`timeout_ms`（默认 5000）、`retry_count`、`retry_on_status`、`retry_non_idempotent`、`load_balance`（`weighted_round_robin` / `consistent_hash`）、`hash_header`、`priority`（默认 100）、`enabled`、`description`。

### 2.6 灰度发布页 — 运行时比例调整（`src/views/GrayReleaseList.vue`）

灰度发布的特色功能是运行时调整灰度比例，调用 PATCH `/gray-releases/:id/percent`，无需重建规则。

```javascript
// 打开比例调整弹窗，回显当前值
function openPercent(row) {
  percentRow.value = row
  percentValue.value = row.gray_percent
  percentVisible.value = true
}

// 提交比例调整（0-100，滑块步进 5）
async function submitPercent() {
  percentSubmitting.value = true
  try {
    await patchGrayPercent(percentRow.value.id, percentValue.value)
    ElMessage.success(`灰度比例已调整为 ${percentValue.value}%`)
    percentRow.value.gray_percent = percentValue.value  // 本地即时更新
    percentVisible.value = false
  } finally {
    percentSubmitting.value = false
  }
}
```

**染色规则处理**：表单中染色规则以 JSON 文本录入，提交时 `JSON.parse` 转为数组传给后端 `stain_rules` 字段（`datatypes.JSON`）。解析失败时提示"染色规则 JSON 格式错误"。

## 3. 接口对接

### 3.1 接口总览

所有管理面接口前缀 `/api/v1`，需 `Authorization: Bearer <token>` 请求头。统一响应格式：

```json
{ "code": 0, "message": "success", "data": {}, "trace_id": "..." }
```

分页响应的 `data` 结构：

```json
{
  "list": [],
  "pagination": { "page": 1, "page_size": 20, "total": 100, "total_pages": 5 }
}
```

### 3.2 各页面接口明细

#### 登录页

| 用途 | 方法 | 路径 | 说明 |
|---|---|---|---|
| 验证 Token | GET | `/api/v1/system/config` | 登录时用此接口验证 Token 有效性 |

#### 运行概览

| 用途 | 方法 | 路径 | 请求参数 | 数据渲染 |
|---|---|---|---|---|
| 配置快照 | GET | `/api/v1/system/config` | 无 | 统计卡片 + 饼图 |
| 触发热更新 | POST | `/api/v1/system/reload` | 无 | 返回 `config_version` |
| 存活探针 | GET | `/healthz` | 无 | 健康状态卡片 |
| 就绪探针 | GET | `/readyz` | 无 | 就绪状态 + 配置版本 |

#### 路由管理

| 用途 | 方法 | 路径 | 请求参数 |
|---|---|---|---|
| 路由列表 | GET | `/api/v1/routes` | `page`, `page_size`, `path`, `method`, `target_service` |

| 创建路由 | POST | `/api/v1/routes` | body: `CreateRouteRequest` |

| 删除路由 | DELETE | `/api/v1/routes/:id` | path: id |
| 启停路由 | PATCH | `/api/v1/routes/:id/status` | body: `{enabled: bool}` |

#### 限流规则

| 用途 | 方法 | 路径 | 请求参数 |
|---|---|---|---|
| 规则列表 | GET | `/api/v1/rate-limits` | `page`, `page_size`, `route_id` |

**关键字段**：`algorithm`（`token_bucket` / `leaky_bucket`）、`rate`（>0）、`capacity`、`limit_by`（`route` / `ip` / `client_id`）。

#### 熔断策略

| 用途 | 方法 | 路径 | 请求参数 |
|---|---|---|---|
| 策略列表 | GET | `/api/v1/circuit-breakers` | `page`, `page_size`, `route_id`, `target_service` |

| 创建策略 | POST | `/api/v1/circuit-breakers` | body: `CreateCircuitBreakerRequest` |
| 删除策略 | DELETE | `/api/v1/circuit-breakers/:id` | path: id |

> **注意**：后端未提供熔断策略的 PUT 更新接口，前端不提供编辑功能，修改需删除后重建。页面已用 tooltip 提示。

**关键字段**：`error_rate_threshold`（1-100）、`sliding_window_size_ms`（默认 10000）、`min_request_count`（默认 20）、`open_duration_ms`（默认 30000）、`half_open_max_requests`（默认 5）。

#### 灰度发布

| 用途 | 方法 | 路径 | 请求参数 |
|---|---|---|---|
| 规则列表 | GET | `/api/v1/gray-releases` | `page`, `page_size`, `route_id` |

**关键字段**：`route_id`（必填）、`gray_version`（必填）、`gray_percent`（0-100）、`hash_key_type`（`ip`/`header`/`cookie`/`user_id`）、`stain_rules`（JSON 数组）。

| 用途 | 方法 | 路径 | 请求参数 |
|---|---|---|---|

> **注意**：服务的详情和删除均按 `service_name` 操作，而非 ID。前端调用时传 `row.service_name`。

### 3.3 开发环境代理

`vite.config.js` 中配置代理，前端开发服务器（5173）将 `/api`、`/healthz`、`/readyz` 转发到网关管理面 `http://127.0.0.1:8081`，避免跨域问题。生产环境建议与后端同源部署（Nginx 反代）或配置 `VITE_API_BASE_URL`。

## 4. 交互实现

### 4.1 表单校验

所有表单使用 Element Plus `el-form` + `rules` 进行校验，必填字段与后端 `binding:"required"` 对齐：

| 页面 | 必填字段 | 额外校验 |
|---|---|---|
| 登录 | token | - |
| 路由 | route_name, path, method, target_service | - |
| 限流 | rule_name, algorithm, rate, capacity | rate > 0（后端校验，前端 min=1） |
| 熔断 | policy_name, error_rate_threshold | error_rate_threshold 1-100 |
| 灰度 | rule_name, route_id, gray_version | gray_percent 0-100（滑块约束） |
| 服务 | service_name | 唯一约束由后端校验（409） |

校验触发方式：`blur`（输入框）/ `change`（选择器），提交时 `formRef.validate()` 全量校验。

### 4.2 状态反馈

- **加载状态**：表格 `v-loading`、按钮 `:loading`、开关 `_statusLoading`，防止重复提交。
- **操作结果**：成功用 `ElMessage.success`，失败由 axios 响应拦截器统一 `ElMessage.error`。
- **空数据**：`el-table` 自带空状态提示。
- **健康状态**：Dashboard 用颜色区分（绿=正常/就绪，红=异常，黄=未就绪）。

### 4.3 弹窗逻辑

| 弹窗类型 | 触发 | 关闭行为 |
|---|---|---|
| 新建/编辑表单 | 点击"新建"或"编辑" | `@closed` 重置表单，避免脏数据 |
| 删除确认 | `ElMessageBox.confirm` | 确认后调用删除 API，取消则无操作 |
| 详情查看 | 点击"详情" | 纯展示，关闭即销毁 |
| 灰度比例调整 | 点击"调整" | 滑块实时预览，"应用"才提交 |
| 退出登录 | 点击"退出" | `ElMessageBox.confirm` 确认后清除 Token 跳转 |

所有表单弹窗 `:close-on-click-modal="false"`，防止误触关闭丢失输入。

### 4.4 异常处理

| 异常场景 | 处理方式 |
|---|---|
| 401 未授权 | 拦截器自动清除 Token + 跳转登录页 + 提示 |
| 409 冲突（路由路径重复/服务名重复） | 拦截器弹出后端 message |
| 429 限流 | 提示"请求过于频繁" |
| 503 熔断 | 提示"服务暂不可用（熔断开启）" |
| 网络异常/超时 | 提示"网络异常" |
| 启停开关失败 | 回滚开关到原状态 |
| 染色规则 JSON 解析失败 | 提示"染色规则 JSON 格式错误"，不提交 |
| 搜索空值 | 空字符串转为 `undefined` 不传参，避免后端误匹配 |

## 5. 运行说明

### 5.1 环境要求

- Node.js >= 18（推荐 20 LTS）
- npm >= 9
- 后端网关管理面运行在 `127.0.0.1:8081`（开发代理目标）

### 5.2 依赖安装

```bash
cd web
npm install
```

### 5.3 启动开发服务器

```bash
npm run dev
```

- 默认地址：`http://localhost:5173`
- 自动打开浏览器
- `/api`、`/healthz`、`/readyz` 代理到 `http://127.0.0.1:8081`
- 支持热更新（HMR）

### 5.4 生产构建

```bash
npm run build
```

- 产物输出到 `dist/` 目录
- 第三方库按 `vue` / `element` / `echarts` 分包，提升缓存命中率
- 构建验证：2319 modules transformed，built in ~23s

### 5.5 预览构建产物

```bash
npm run preview
```

### 5.6 部署建议

生产环境将 `dist/` 目录交由 Nginx 托管，并配置反向代理：

```nginx
server {
    listen 80;
    root /usr/share/nginx/html;
    index index.html;

    # 前端路由 history 模式 fallback
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 代理到网关管理面
    location /api/ {
        proxy_pass http://gateway-admin:8081;
        proxy_set_header Host $host;
    }
    location /healthz { proxy_pass http://gateway-admin:8081; }
    location /readyz  { proxy_pass http://gateway-admin:8081; }
}
```

若前后端不同源，设置 `.env.production` 中 `VITE_API_BASE_URL=http://网关地址:8081`。

### 5.7 默认登录凭证

开发环境默认 Token（来自 `config/default.yaml`）：

```
Token: admin-token-dev-001
操作人: admin（可留空，默认 admin）
```

### 6.2 验证步骤

**前置条件**：启动网关后端（`cd go-api-gateway && go run ./cmd/gateway`），确保管理面 8081 端口可访问。

#### Step 1：登录验证
1. 访问 `http://localhost:5173`，自动跳转 `/login`
2. 输入错误 Token → 提示"Token 无效或网关不可用"
3. 输入 `admin-token-dev-001` → 登录成功，跳转 `/dashboard`
4. 刷新页面 → 保持登录状态（Token 在 localStorage）

#### Step 2：Dashboard 验证
1. 健康状态卡片显示"正常"/"就绪"
2. 统计卡片显示各资源计数（初始可能为 0）
3. 饼图正常渲染
4. 点击"触发热更新" → 提示成功，版本号更新

#### Step 3：路由管理验证
1. 点击"新建路由"，填写必填项 → 创建成功，列表出现新记录
2. 搜索路径关键字 → 列表正确过滤
3. 切换启用开关 → 状态变更，失败时回滚
4. 点击"编辑" → 表单回显正确，修改后保存成功
5. 点击"删除" → 确认后删除，列表刷新
6. 创建重复 path+method → 提示"路由路径与方法组合已存在"

#### Step 4：限流规则验证
1. 新建令牌桶规则（rate=100, capacity=200）→ 创建成功
2. 新建漏桶规则 → 算法标签正确显示
3. rate 填 0 → 后端校验失败提示
4. 编辑/删除规则正常

#### Step 5：熔断策略验证
1. 新建熔断策略（错误率阈值 50%，熔断时长 30s）→ 创建成功
2. 点击"详情" → 所有字段正确展示
3. 删除策略 → 确认后删除
4. 页面无"编辑"按钮（后端未提供 PUT 接口，符合预期）

#### Step 6：灰度发布验证
1. 新建灰度规则（绑定路由 ID，灰度版本 v2，比例 10%）→ 创建成功
2. 列表中进度条显示 10%（绿色）
3. 点击"调整" → 滑块拖到 50% → 应用成功，列表即时更新
4. 拖到 100% → 出现全量切换警告提示
5. 染色规则填入非法 JSON → 提示格式错误

#### Step 7：服务管理验证
1. 注册服务（service_name=test-service）→ 成功
2. 重复注册同名服务 → 提示"服务名已存在"
3. 点击"详情" → 字段正确展示
4. 删除服务 → 确认后删除

#### Step 8：鉴权与异常验证
1. 清除 localStorage 后访问 `/routes` → 跳转登录页
2. 登录后停止后端 → 操作提示"网络异常"
3. 退出登录 → 确认后跳转登录页

| 项 | 说明 |
|---|---|
| 熔断策略无编辑 | 后端未提供 PUT 接口，前端仅支持新建/删除/详情；后端补充后可扩展编辑 |

| 实时监控 | Dashboard 仅展示配置统计，未接入 Prometheus 实时指标（QPS/延迟/错误率）；后续可接入 `/metrics` 或 Prometheus API |
| 国际化 | 当前仅中文，Element Plus 已配置中文语言包，可扩展 i18n |
