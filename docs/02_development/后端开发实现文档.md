### 1.3 依赖说明

- **etcd 不可用时**：网关启动不阻塞，打印警告，服务注册表为空，反向代理返回502
- **Redis 不可用时**：网关启动不阻塞，限流引擎运行在本地内存模式（单机限流）
- **SQLite 默认驱动**：使用 `glebarez/sqlite`（基于 `modernc.org/sqlite` 纯Go实现），支持 `CGO_ENABLED=0` 静态编译
- **配置热更新**：当前版本通过 `POST /api/v1/system/reload` 手动触发；etcd Watch 自动触发在迭代二实现

### 2.2 启动时序（9步）

```
main.go
  │
  ├─ ① config.Load()          加载YAML配置 + 环境变量覆盖
  ├─ app.New(ctx, cfg)
  │    ├─ ② logger.Init()     初始化zap日志（JSON格式，可选异步）
  │    ├─ ③ store.NewDB()     连接SQLite/MySQL + AutoMigrate 7张表
  │    ├─ ④ snapManager.Reload()  从DB构建不可变配置快照
  │    ├─ ⑤ registry.NewDiscovery()  连接etcd + 全量拉取 + 启动Watch
  │    ├─ ⑥ store.NewRedisClient()   连接Redis + Ping验证
  │    ├─ 初始化核心引擎（路由匹配器/限流器/熔断器/灰度路由器/负载均衡器）
  │    └─ ⑧ startAdminServer()  启动管理面HTTP Server（:8081）
  ├─ ⑨ app.Start() → startDataServer()  启动数据面HTTP Server（:8080）【最后启动】
  │
  └─ 等待 SIGINT/SIGTERM → app.Stop()  逆序优雅关闭（30s超时）
```

**关键设计**：数据面最后启动（步骤⑨），确保管理面、配置、依赖全部就绪后才对外提供流量；关闭时数据面先关闭，拒绝新请求但允许在途请求完成。

### 2.3 核心算法说明

#### 2.3.1 平滑加权轮询（WRR）

```
算法（nginx smooth WRR）：
1. 每个实例 current_weight += weight
2. 选择 current_weight 最大的实例
3. 选中实例 current_weight -= total_weight

示例：实例A(weight=5), B(weight=1), C(weight=1)
序列：A A A A B A C → 分布均匀，无连续集中
```

代码位置：`internal/loadbalance/loadbalance.go` → `WeightedRoundRobin.Select()`

#### 2.3.2 一致性哈希

```
参数：150个虚拟节点/权重单位
环构建：每个实例生成 weight*150 个虚拟节点，按hash值排序
查询：murmur3(requestKey) → 二分查找第一个 hash >= key 的节点 → 顺时针最近
```

代码位置：`internal/loadbalance/loadbalance.go` → `ConsistentHash`

#### 2.3.3 熔断滑动窗口

```
结构：10个桶，每桶覆盖 window_size/10 时长
推进：每次记录时按时间差推进桶指针，经过的桶清零
统计：聚合10个桶的 total/errors/slow
触发：total >= min_request_count AND (error_rate >= threshold OR slow_rate >= threshold)
```

代码位置：`internal/circuitbreaker/circuit_breaker.go` → `SlidingWindow`

#### 2.3.4 灰度两级决策

```
第一级（最高优先级）：染色规则匹配
  - header精确匹配 / cookie精确匹配 / query精确匹配 / user_id IN列表 / ip匹配
  - 命中 → 直接路由到灰度版本

第二级：哈希比例分流
  - key = ip / header / cookie / user_id（可配置）
  - murmur3(key) % 100 < gray_percent → 灰度版本，否则稳定版本
```

代码位置：`internal/gray/gray_router.go` → `Router.Calculate()`

## 3. 接口定义

### 3.1 通用约定

- **管理面基础URL**：`http://{host}:8081/api/v1`
- **数据面基础URL**：`http://{host}:8080`（业务流量转发）
- **鉴权方式**：`Authorization: Bearer {token}`（管理面所有 `/api/v1/*` 端点，`/healthz`、`/readyz`、`/metrics` 除外）
- **内容类型**：`application/json`
- **统一响应格式**：

```json
{
  "code": 0,
  "message": "success",
  "data": { },
  "trace_id": "778f0d26736e2422fc59a83c00d2cc41"
}
```

- **分页响应格式**（data 内嵌）：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "list": [ ],
    "pagination": {
      "page": 1,
      "page_size": 20,
      "total": 100,
      "total_pages": 5
    }
  },
  "trace_id": "..."
}
```

### 3.2 系统运维接口

#### 3.2.1 健康检查（Liveness）

```
GET /healthz
```

- **鉴权**：无需
- **响应 200**：`{"status":"ok"}`

#### 3.2.2 就绪探针（Readiness）

```
GET /readyz
```

- **鉴权**：无需
- **响应 200**：`{"status":"ready","config_version":1}`

```

- **鉴权**：无需
- **响应**：Prometheus text format

```

- **鉴权**：需要

### 3.3 路由管理接口

#### 3.3.1 创建路由

```
POST /api/v1/routes
```

**请求体**：

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| route_name | string | 是 | - | 路由名称 |
| path | string | 是 | - | 匹配路径（支持前缀匹配） |
| method | string | 是 | - | HTTP方法（GET/POST/PUT/DELETE/PATCH/*） |
| target_service | string | 是 | - | 目标服务名 |
| rewrite_path | string | 否 | "" | 路径重写（支持 `strip_prefix=/xxx`） |
| timeout_ms | int | 否 | 5000 | 超时时间（毫秒） |
| retry_count | int | 否 | 0 | 重试次数 |
| retry_on_status | string | 否 | "" | 重试状态码（逗号分隔，如 "502,503,504"） |
| retry_non_idempotent | bool | 否 | false | 是否对非幂等请求重试 |
| load_balance | string | 否 | "weighted_round_robin" | 负载均衡策略（weighted_round_robin/consistent_hash） |
| hash_header | string | 否 | "" | 一致性哈希使用的Header名 |
| priority | int | 否 | 100 | 优先级（越小越高） |
| enabled | bool | 否 | true | 是否启用 |
| description | string | 否 | "" | 描述 |

**响应 200**：返回创建的路由对象（含 id、created_at 等）

**错误码**：
- `40101`：路径+方法组合已存在（409 Conflict）
- `40001`：参数校验失败（400 Bad Request）

#### 3.3.2 路由列表

```
GET /api/v1/routes?page=1&page_size=20&path=&method=&target_service=
```

**查询参数**：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| page | int | 否 | 页码，默认1 |
| page_size | int | 否 | 每页条数，默认20，最大100 |
| path | string | 否 | 路径模糊匹配 |
| method | string | 否 | HTTP方法精确匹配 |
| target_service | string | 否 | 目标服务精确匹配 |

**响应 200**：分页响应，list 为路由对象数组

#### 3.3.3 路由详情

```
GET /api/v1/routes/{id}
```

**响应 200**：路由对象  
**响应 404**：`{"code":40103,"message":"路由不存在"}`

```

```

- **请求体**：同创建路由
- **乐观锁**：基于 `version` 字段，冲突返回 409
- **响应 200**：更新后的路由对象

#### 3.3.5 删除路由

```
DELETE /api/v1/routes/{id}
```

- **软删除**：设置 `deleted_at`，数据保留
- **响应 200**：`{"id":"...","deleted":true}`

#### 3.3.6 启用/禁用路由

```
PATCH /api/v1/routes/{id}/status
```

**请求体**：`{"enabled": false}`

**响应 200**：`{"id":"...","enabled":false}`

**请求体**：

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| service_name | string | 是 | - | 服务名（唯一） |
| display_name | string | 否 | "" | 显示名称 |
| health_check_path | string | 否 | "/health" | 健康检查路径 |
| health_check_interval | int | 否 | 10 | 健康检查间隔（秒） |
| health_check_timeout | int | 否 | 3 | 健康检查超时（秒） |
| default_weight | int | 否 | 1 | 默认权重 |
| description | string | 否 | "" | 描述 |

**错误码**：
- `40501`：服务名已存在（409）

#### 3.7.2 服务列表/详情/删除

```
GET    /api/v1/services?page=1&page_size=20
GET    /api/v1/services/{name}
DELETE /api/v1/services/{name}
```

### 3.8 数据面响应头

网关在转发请求时会注入/返回以下Header：

| Header | 方向 | 说明 |
|--------|------|------|
| `X-Trace-Id` | 响应 | 分布式追踪ID（100%请求注入） |
| `traceparent` | 请求（转发到后端） | W3C TraceContext格式：`00-{traceid}-{spanid}-01` |
| `X-RateLimit-Limit` | 响应 | 限流上限（被限流时返回） |
| `X-RateLimit-Remaining` | 响应 | 剩余配额（被限流时返回） |
| `Retry-After` | 响应 | 重试等待时间（被限流时返回） |
| `X-Circuit-Breaker` | 响应 | 熔断状态（熔断时返回 "open"） |

```bash
cd deploy/compose
docker-compose up -d
```

启动的服务：
- `gateway`：网关（8080:8080 数据面，127.0.0.1:8081:8081 管理面）
- `etcd`：etcd v3.5.15（2379）
- `redis`：Redis 7.2（6379）
- `test-service-a`：测试服务A（8090:8080）

- **非root用户**：运行时使用 `nonroot` 用户
- **HEALTHCHECK exec形式**：`CMD ["/app/gateway", "healthcheck"]`，不依赖shell

## 附录A：关键设计决策记录

| 决策项 | 选择 | 理由 |
|--------|------|------|
| SQLite驱动 | glebarez/sqlite（modernc） | 架构要求CGO_ENABLED=0，mattn/go-sqlite3需要CGO |
| 配置热更新触发 | 手动API + etcd Watch（迭代二） | 迭代一先实现手动触发，保证核心路径稳定 |
| 限流Redis预取 | 本地内存为主，Redis为迭代二增强 | 保证请求路径无网络IO，nanosecond级响应 |
| 熔断全局协调 | 本地滑动窗口判断，Redis半开计数为迭代二 | 迭代一先实现单机熔断，保证功能完整 |
| 管理面鉴权 | 静态Token多映射 | 架构P2-6要求，迭代一不引入OAuth2复杂度 |
| 容器运行时 | distroless/static | 无shell、无libc，攻击面最小，符合P2-10 |
