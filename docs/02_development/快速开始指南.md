# Go API Gateway 快速开始指南（新手友好版）

> 本文档专为**完全没接触过这个项目**的用户编写，跟着步骤一步步来，保证能跑起来。

---

## 一、这个项目是干什么的？

简单说，这是一个 **API 网关**。你可以把它理解成一个"前台接待员"：

- 所有外部请求先到网关（8080端口）
- 网关根据你配置的"路由规则"，把请求转发给后面的真实业务服务
- 同时还能做限流、熔断、灰度发布、负载均衡等高级操作

项目包含三部分：

| 部分 | 作用 | 默认端口 |
|------|------|----------|
| 网关后端（Go） | 核心网关，负责转发请求 | 8080（数据面）/ 8081（管理面） |
| 管理前端（Vue） | 可视化管理界面，鼠标点一点就能配置 | 5173 |
| 测试后端 | 一个简单的模拟服务，用来演示网关转发效果 | 9001 |

## 二、两种运行方式，选一种就行

### 方式 A：本地脚本运行（推荐新手）

**优点**：不用装 Docker，改代码方便，出问题好排查
**需要装**：Go 1.22+、Node.js 18+（脚本会帮你检查）

### 方式 B：Docker 一键部署

**优点**：环境隔离好，一条命令启动所有东西（含 etcd、redis）
**需要装**：Docker Desktop

> **不知道选哪个？** 选方式 A，跟着下面的步骤走就行。

## 三、方式 A：本地脚本运行（详细步骤）

### 第 0 步：打开项目文件夹

找到项目文件夹 `go-api-gateway`，进入后能看到 `scripts` 文件夹。
后面所有操作都在 `scripts` 文件夹里**双击脚本**就行，不用敲命令。

### 第 1 步：检查环境（双击 `01-检查环境.bat`）

双击运行后，会自动检查你电脑上有没有装 Go 和 Node.js。

- 如果显示"环境检查全部通过" → 继续下一步
- 如果有红色的 ✗ → 根据提示去下载安装，装完再跑一次这个脚本

**需要安装的软件（如果没装的话）：**
- Go：https://go.dev/dl/ （下载 Windows 版本，一路下一步安装）
- Node.js：https://nodejs.org/ （下载 LTS 版本，一路下一步安装）

> 装完软件后**关掉所有黑窗口重新打开**，否则可能检测不到。

### 第 2 步：安装依赖（双击 `02-安装依赖.bat`）

这一步会自动下载项目需要的代码库（类似手机装 APP）。

- 第一次运行可能需要几分钟，取决于网速
- 看到"全部依赖安装完成"就成功了
- 以后再启动不需要重复这步（除非你删了依赖文件夹）

### 第 3 步：一键启动所有服务（双击 `06-一键启动全部.bat`）

这是最关键的一步。双击后会**弹出三个黑窗口**，分别是：

1. **测试后端-9001**：模拟的业务服务
2. **网关后端-8080/8081**：核心网关
3. **管理前端-5173**：可视化管理界面

> **三个窗口都不要关！** 关了对应服务就停了。

等大约 5-10 秒，让服务都启动完成。你会看到各个窗口输出启动日志。

### 第 4 步：打开管理后台，登录

打开浏览器，访问：

```
http://localhost:5173
```

会看到登录页面，输入：

| 字段 | 值 |
|------|-----|
| 访问 Token | `admin-token-dev-001` |
| 操作人 | 留空就行（默认 admin） |

点"登录"按钮，就能进入管理后台了。

> Token 就是密码，这个项目用的是静态 Token 认证，没有传统的"注册账号"功能。

### 第 5 步：体验核心主流程（两种方式任选）

#### 方式 5-A：自动演示（推荐，双击 `08-演示主流程.bat`）

如果你想**快速看到效果**，直接双击这个脚本，它会自动帮你完成：
1. 创建一个服务
2. 创建一条路由规则
3. 查看列表确认
4. 通过网关访问验证

脚本跑完后，你再刷新管理后台的"路由管理"和"服务管理"页面，就能看到刚才创建的数据了。

#### 方式 5-B：手动操作（推荐，能理解每个步骤）

跟着下面在管理后台里点一点：

##### 5-B-1：创建一个服务

1. 左侧菜单点"服务管理"
2. 点"新增服务"按钮
3. 填写：
   - 服务名称：`test-service`
   - 显示名称：`我的测试服务`
   - 其他保持默认
4. 点"确定"

> 服务就相当于你公司里的一个"部门"，后面路由会把请求转发给这个部门。

##### 5-B-2：创建一条路由规则

1. 左侧菜单点"路由管理"
2. 点"新增路由"按钮
3. 填写：
   - 路由名称：`测试路由`
   - 路径：`/test/`（注意末尾有斜杠）
   - 方法：选 `*`（表示所有 HTTP 方法都匹配）
   - 目标服务：选 `test-service`
   - 路径重写：`strip_prefix=/test`（意思是转发时把 /test 前缀去掉）
   - 超时时间：`5000`
   - 其他保持默认
4. 点"确定"

> 路由规则就是告诉网关："凡是 /test/ 开头的请求，都转发给 test-service 这个服务"。

##### 5-B-3：列表里看得到

- 在"路由管理"页面，你应该能看到刚才创建的"测试路由"
- 在"服务管理"页面，你应该能看到刚才创建的"test-service"

##### 5-B-4：验证网关转发真的生效了

打开一个新的浏览器标签页，访问：

```
http://localhost:8080/test/hello
```

如果看到类似下面的 JSON 输出，就说明成功了：

```json
{
  "backend_port": "9001",
  "request_count": 1,
  "path": "/hello",
  "method": "GET",
  "timestamp": "2026-10-10T..."
}
```

**发生了什么？**
1. 你的浏览器请求了 `localhost:8080/test/hello`（网关的8080端口）
2. 网关匹配到了"/test/"这条路由规则
3. 网关把 `/test` 前缀去掉，变成 `/hello`
4. 网关转发给测试后端（9001端口）
5. 测试后端返回结果，网关再转给你的浏览器

## 四、方式 B：Docker 一键部署

如果你装了 Docker Desktop，用这种方式更简单：

### 第 1 步：启动 Docker Desktop

确保 Docker Desktop 正在运行（任务栏有鲸鱼图标）。

### 第 2 步：一键启动（双击 `09-Docker一键启动.bat`）

会自动构建并启动 5 个容器：
- gateway（网关）
- etcd（服务发现）
- redis（缓存/限流）
- test-service-a（测试服务A，端口8090）
- test-service-b（测试服务B，端口8091）

首次构建需要几分钟，以后就快了。

### 第 3 步：访问和操作

- 网关管理面 API：http://localhost:8081
- 网关数据面（代理）：http://localhost:8080
- 测试服务A：http://localhost:8090
- 测试服务B：http://localhost:8091

> Docker 方式没有前端管理界面（5173），需要用 API 或者自己启动前端连接。推荐用方式 A 体验可视化界面。

### 停止 Docker 环境

双击 `10-Docker停止.bat` 即可。

## 七、管理后台主要功能介绍

登录后左侧菜单能看到：

| 菜单 | 作用 | 对应"创建数据→列表"流程 |
|------|------|------------------------|
| 仪表盘 | 看整体统计信息 | - |
| 路由管理 | 配置哪些请求转发给哪个服务 | 创建路由 → 路由列表 |
| 服务管理 | 管理后端服务元数据 | 创建服务 → 服务列表 |
| 限流管理 | 配置 QPS 限流规则 | 创建限流 → 限流列表 |
| 熔断管理 | 配置熔断策略（后端挂了就快速失败） | 创建熔断 → 熔断列表 |
| 灰度发布 | 配置灰度发布规则（按比例切流量） | 创建灰度 → 灰度列表 |

每个模块的操作流程都一样：**点新增 → 填表单 → 确定 → 列表里看得到**。

## 八、常见问题排查

### Q1：双击脚本后黑窗口一闪而过？

**原因**：脚本出错了但窗口关了看不到。
**解决**：先打开一个 cmd 窗口，把脚本拖进去回车运行，这样能看到错误信息。

### Q2：启动后访问 localhost:5173 打不开？

**原因**：前端还没启动完，或者启动失败了。
**解决**：
1. 看"管理前端-5173"那个黑窗口有没有报错
2. 等 10 秒再刷新试试
3. 如果报缺少依赖，运行 `02-安装依赖.bat`

### Q3：登录时提示"Token 无效或网关不可用"？

**原因**：网关后端没启动，或者 Token 输错了。
**解决**：
1. 确认"网关后端-8080/8081"窗口在运行
2. 确认 Token 是 `admin-token-dev-001`（注意没有空格）
3. 浏览器访问 http://localhost:8081/healthz ，如果返回 `{"status":"ok"}` 说明网关正常

### Q4：通过网关访问返回 502 bad gateway？

**原因**：网关转发请求时，后端服务没响应。
**解决**：
1. 确认"测试后端-9001"窗口在运行
2. 直接访问 http://localhost:9001/hello ，看测试后端本身能不能通
3. 确认路由的目标服务名是 `test-service`，和配置文件里的 static_backends 一致

### Q5：通过网关访问返回 404 route not found？

**原因**：请求路径没有匹配到任何路由规则。
**解决**：
1. 确认路由路径配置的是 `/test/`（末尾有斜杠）
2. 访问的 URL 是 `http://localhost:8080/test/hello`（不是 /test，是 /test/hello）
3. 确认路由是启用状态（路由列表里 enabled 为 true）

### Q6：端口被占用了怎么办？

**原因**：其他程序用了 8080/8081/5173/9001 中的某个端口。
**解决**：
1. 运行 `07-停止所有服务.bat` 先停掉之前的服务
2. 如果还不行，重启电脑（最简单）
3. 或者修改 `config/local-demo.yaml` 里的端口号

### Q7：想重置所有数据怎么办？

**解决**：
1. 停止所有服务（运行 `07-停止所有服务.bat`）
2. 删除项目里的 `data/gateway.db` 文件
3. 重新启动，数据库会自动重建（空的）

## 九、下一步可以学什么？

跑通基础流程后，你可以尝试：

1. **限流**：在"限流管理"里创建一条限流规则，绑定到刚才的路由，然后快速刷新页面看 429 报错
2. **熔断**：在"熔断管理"里创建熔断策略，然后把测试后端关了，看网关返回 503
3. **负载均衡**：启动两个测试后端（不同端口），配置静态后端，看网关轮询转发
4. **灰度发布**：配置灰度规则，按比例把流量切到不同版本的后端
