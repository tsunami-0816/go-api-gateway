#### BUG-P1-005：一致性哈希负载均衡的 Hash Ring 从未构建，永远 fallback 到第一个实例

| 项目 | 内容 |
|---|---|
| **严重等级** | P1 严重 |
| **验证结果** | ❌ **未通过**（修复时引入锁重入死锁，一致性哈希完全不可用） |
| **验证方式** | 端到端实测 + 代码根因定位 |
| **实测数据** | 路由 path=/api/chash, load_balance=consistent_hash, hash_header=X-User-ID；发送请求 → **HTTP 000, Time: 5.015s（超时）** |
| **根因定位** | `ConsistentHash.Select()` 方法（loadbalance.go 第 146-188 行）存在**锁重入死锁**： 1. 第 161-169 行：`needRebuild` 为 true 时，先获取 `ch.mu.Lock()` 2. 第 166 行：持有锁的状态下调用 `ch.UpdateRing(instances)` 3. `UpdateRing()` 方法（第 120-143 行）第 121 行又执行 `ch.mu.Lock()` 4. `sync.Mutex` 不可重入，当前 goroutine 永久阻塞，请求挂起直至超时 |
| **影响范围** | 所有配置 `load_balance=consistent_hash` 的路由完全不可用，请求 100% 超时。这是 P1-005 修复时引入的**回归 Bug**。 |
| **可复现性** | 100% 可复现。首次调用 `Select()` 时 `ch.ring` 为空，`needRebuild=true`，触发死锁。 |
| **修复建议** | 方案 A（推荐）：将 `UpdateRing()` 的建环逻辑提取为不带锁的内部方法 `buildRingLocked(instances)`，`Select()` 持有锁时直接调用；`UpdateRing()` 作为公开方法保留锁。 方案 B：在 `Select()` 调用 `UpdateRing()` 前释放锁，调用后重新获取锁（需注意竞态条件）。 |

## 四、引入新 Bug（修改影响范围内）

### REGRESSION-001【P1 严重】一致性哈希 Select() 方法锁重入死锁，所有 consistent_hash 路由请求超时

| 项目 | 内容 |
|---|---|
| **严重等级** | P1 严重 |
| **引入来源** | BUG-P1-005 修复时引入 |
| **影响模块** | `internal/loadbalance/loadbalance.go` → `ConsistentHash.Select()` + `UpdateRing()` |
| **Bug 描述** | `Select()` 方法在 `needRebuild` 分支中先获取 `ch.mu.Lock()`（第 162 行），然后在持有锁的状态下调用 `ch.UpdateRing(instances)`（第 166 行）。而 `UpdateRing()` 方法内部第一行就是 `ch.mu.Lock()`（第 121 行）。Go 的 `sync.Mutex` 不可重入，导致当前 goroutine 永久阻塞在 `UpdateRing()` 的锁获取上，请求挂起直至路由超时（504）。 |
| **复现步骤** | 1. 创建路由 load_balance=consistent_hash 2. 注册 2 个后端实例 3. 发送任意请求到该路由 |
| **预期结果** | 请求按一致性哈希分发到后端，返回 200 |
| **实际结果** | 请求挂起 5s 后超时返回 504（或客户端超时） |
| **影响范围** | 所有配置 `load_balance=consistent_hash` 的路由完全不可用，需要会话保持（粘性会话）的业务场景无法工作。 |
| **可复现性** | 100% 可复现（首次调用 Select() 时 ring 为空，必然触发 needRebuild 和死锁） |
| **修复方案** | **方案 A（推荐）**：将 `UpdateRing()` 的建环逻辑提取为不带锁的内部方法 `buildRingLocked(instances []*registry.Instance)`，`Select()` 持有锁时直接调用 `buildRingLocked()`；`UpdateRing()` 作为公开方法保留锁并调用 `buildRingLocked()`。 **方案 B**：在 `Select()` 调用 `UpdateRing()` 前释放 `ch.mu.Unlock()`，调用后重新获取锁（需注意 double-check 竞态条件）。 |
